Up to4 concurrent local uploads; ordinary API limits plus30 upload attempts/vendor/hour. Stream at most5MiB into an owner-private temporary file with incremental SHA256/MD5 and a12-byte format signature. Accept octet-stream or matching JPEG/PNG/WebP type; reject empty/oversize/unsupported/mismatched type, encoded transport and multipart. Signature checks are quarantine admission only, not decoding/animation/dimension validation. Always close/delete temporary files. No filename, raw bytes or credentials are persisted in PostgreSQL/logs.

Schema47 adds immutable upload source identity/hash/size/MIME/key, a120-second fenced lease, raw confirmation/deletion metadata and one durable pending processing job per asset. Reserve source+QUEUED asset+body-free audit atomically before any provider write. Other same-vendor members may retry. Different bytes/size/type409 IDEMPOTENCY_MISMATCH; in-flight live lease409 UPLOAD_IN_PROGRESS. Expired lease may be reacquired only with identical source; no uncertain outcome is released/rebound. Identical confirmed uploads return current metadata202 without new provider work/job/audit. Existing gallery-only metadata IDs cannot be adopted as uploads.

Object key is deterministic quarantine/<vendor>/<asset>, in an isolated private EU R2 bucket. SDK2.55.13 s3/url-connection-client only; regionauto, static explicit credentials, no default credential chain, no public ACL/URL/presigning. Exact file length, MD5 and SHA256 metadata; no SDK automatic retries, no chunked encoding, bounded calls. HEAD verifies immutable source; absent key uses atomic If-None-Match:* PUT then HEAD verifies. Existing mismatched metadata503 fails closed; conditional conflicts re-HEAD, never overwrite. Timeout/unknown outcome retains the source/lease for later HEAD reconciliation. Never call providers in a database transaction.

Final commit reauthorizes, checks the exact lease fence/expiry and current claim, confirms raw source, inserts the single pending processing job and required audit atomically. Commit loss retries return the same asset/job; definite rollback after object storage leaves a tracked reservation for same-source recovery. Later deactivation/CSRF failure cannot enqueue processing. GET metadata requires current same-vendor catalogue access and exposes Asset fields only, never keys/hash/URLs/raw bytes. QUEUED may represent an incomplete reservation; only raw-confirmed jobs are claimable by a future decoder. No READY producer is added.

Technical cleanup uses a separate internal maintenance service: claim uploads with no progress for at least1h and no live upload lease, lock vendor then asset/source, prevent further uploads/processing, cancel the pending job and mark FAILED/UPLOAD_EXPIRED. Delete the deterministic raw key outside transactions, then atomically tombstone DELETED with retained source identity and immutable technical events. Delete/commit failure retains the claim for repeat-safe retry; no untracked compensating delete after uncertain upload. Confirmed queued raw files are included if abandoned; future processing must refresh progress and hold its own lease before using this cleanup path. READY/actively processing/referenced files excluded. Scheduler is separately disabled by default; local tests invoke it explicitly. Physical processed-image24h cleanup remains next.

Local fake wire service verifies real SDK requests; PostgreSQL tests use a deterministic fake port. Identity→media API is added to the allowed acyclic graph; media uses existing catalogue/audit APIs. New runtime grants are constrained to required upload metadata/job/events and QUEUED asset admission; runtime still cannot mint READY proof. Executed evidence is separate.

Separate review refinement: cleanup retains a zero-byte private storage tombstone at the same deterministic key after removing raw bytes. A bounded HEAD/delete/conditional-marker/HEAD sequence (at most3 attempts) must confirm this fence before recording DELETED. Marker metadata contains no raw content.
