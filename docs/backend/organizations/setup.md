Explicit resend requires UUIDv4 Idempotency-Key and current invitation revision; atomically changes generation/token, invalidates old email proofs and queues one encrypted intent. Replay reauthorizes sender, preserves original success seven days then tombstone, never returns tokens. Revoke is natural desired-state identity. Password policy/common-compromised checks are the managed provider's mandatory G-02 obligation, never weakened locally. This contract's required-password setup path creates a usable password mapping after positive provider confirmation. No implicit external/email match or invented provider subject; existing Google/Apple linking remains separate. External-only initial-binding setup is not introduced by silently changing this password contract.
- Before one provider write, commit a durable setup intent with candidate local organization/owner/provider UUIDs, pinned tenant and normalized public-field digest (never password/hash), consume the mailbox proof, and reserve email plus country/type/normalized registration. Provider exchange occurs outside transactions. PREPARED/UNKNOWN never redispatch; repeat with valid current recipient proofs confirms read-only. Positive APPLIED permits atomic original organization+verified owner+managed mapping+plan assignment+invitation consumption+audit+claim release. Final failure retains APPLIED for same-intent reconciliation. Successful replay revalidates token/proof possession and original nonsecret intent for seven days, never changes password or returns a session. New proof can renew mailbox authority for the same uncertain intent while invitation remains valid.
- Address reservations cover existing current/reserved/in-flight claims and setup holds globally, including setup inserts and email changes. Registration reservations prevent competing provider creations for one country/type identifier. Unknown outcomes have no automatic expiry/release; sender revocation/deactivation or invitation expiry after remote creation prevents activation and retains a BLOCKED intent for assisted provider resolution. No automatic remote deletion or force-clear. Definitive password-policy rejection consumes that proof but releases holds; a fresh explicit mailbox proof permits a corrected password attempt. Alternate/new payload against an uncertain intent conflicts.
