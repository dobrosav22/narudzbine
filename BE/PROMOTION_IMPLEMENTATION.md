# Vendor promotion lifecycle

2026-10-19. Six operations: listPromotions/createPromotion/getPromotion/updatePromotion/stopPromotion/archivePromotion. Existing D-PRI-005–015/022–032, D-PLAN-012 and R-CAT-015 govern behavior; concrete refinements under D-GOV-005 were recorded in DESIGN_SPEC before implementation.

- Schema28 adds genuine promotion definitions, immutable creation receipts/history and operative product/buyer references, reusing actual catalogue promotion identities/category-reference guards. Historical taxonomy-only identities/references are preserved; no definition, schedule, discount or completed action is fabricated. Values use strict exact decimal strings; percentages>0..100 with at most two decimals, fixed replacement prices0..999999999.99. No coupons, pause/resume, redemption caps or announcement deliveries.
- JSON byte bounds remain16 KiB for authentication. Promotion definitions and agreed-price selected confirmation use128 KiB so approved1000-ID lists fit; byte overflow413 differs from invalid item count422. Deferred aggregate/reference checks avoid scanning an entire target set for every changed target row.
- Schedule input requires local seconds and an explicit valid offset in Europe/Belgrade or Europe/Sarajevo. Reject DST gaps/invalid overlap offsets, start<=the current write instant, end<=start and elapsed duration>366 days. Definition edits require both the old start and proposed start to remain future. Read/evaluation state uses one injected Clock instant: start inclusive, end exclusive; STOPPED permanent, archive separate. Current-revision repeat stop/archive is a no-op. Ended offers archive rather than newly stop.
- Product/category union intersects buyer scope. ALL requires empty IDs; SELECTED requires a nonempty appropriate set; IDs must be distinct and at most1000 per list. Products must have genuine own-vendor details (inactive/archived allowed without activation); categories must be live own-vendor CATEGORY records; selected buyers need actual active domestic relationships at save. No tag-target field was added. Current membership/category rules govern later calculations.
- Typed vendor guards and deferred final-reference constraints prevent foreign bindings, mixed kinds, detached live target sets or partial reference replacement. Category deletion remains blocked until explicit cleanup. Stopped promotions still reference targets until archival; stopped/ended archival releases operative references while keeping the original definition/ID-label snapshot. Promotion now returns targetLabels to fulfill the design's frozen-label requirement; targets retains its existing ID/mode shape. Labels are captured on creation or an actual pre-start definition edit; an otherwise unchanged save preserves the original snapshot.
- Own-vendor owner/admin/staff use uniform EDIT_PROMOTIONS, with current authorization in the committing transaction. Coherent reads/writes acquire the vendor organization guard before actor/session locks; lifecycle/reference/revocation races serialize. Buyers/platform/foreign vendors cannot use these routes. Browser writes retain CSRF/origin, strict JSON/query validation and RFC9457 errors. Support reads remain a separate audited-context workflow.
- Client UUIDv7 identifies creation. Keyed canonical intent includes normalized text/decimal scale, sorted IDs and resolved UTC instants. Same actor/vendor/id/intent replays the original creation result for seven days (200, versus201 for creation), even after edits/start/stop; changed intent409, inaccessible context404, exact expiry409 REPLAY_EXPIRED with authorized resourceId. Receipts and identities cannot be reassigned/deleted. Ordinary edits/actions use promotion/v1 revision tokens, without a separate retry key. Genuine changes atomically record immutable snapshots/actor/time and field-name audit. No-op has no history/audit/revision increment.
- Internal candidate evaluation accepts a validated resolved unit price and requires a current active connection. It uses actual current product category plus stored selection and one running/nonarchived window. Fixed replaces; percentage arithmetic stays exact until half-up unit rounding. Only a strictly lower rounded result is attributed; no stacking/increase/equal-baseline attribution. Earliest creation then database-compatible UUID string order breaks equal savings; edits never change creation time. This is a prerequisite, not a buyer offer or stock/order authorization.

Runtime additions: SELECT/INSERT/UPDATE on promotion; SELECT/INSERT on promotion_creation/promotion_history/catalogue_promotion_identity; SELECT/INSERT/DELETE on promotion_product/promotion_buyer/catalogue_promotion_taxonomy. No runtime promotion DELETE, receipt/history UPDATE/DELETE or target-binding UPDATE is required. Controlled migration owner alone applies V20261019180000; readiness expects28.
