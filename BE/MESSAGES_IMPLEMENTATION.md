# Order messages refinement

Selected2026-10-20 under D-GOV-005 before dependent code; assistant selections, not user answers. Implements createMessage/listOrderMessages under R-ORD-018/019/020/025/041, R-ORG-024/026, R-NOT-003/013 and targeted replay conventions.

All active verified buyer/vendor owner/admin/staff may read their original shared order thread. SEND_ORDER_MESSAGE is uniform across these roles, independent of buyer staff submission restriction; platform commercial writes remain denied. New messages require either an ACTIVE domestic relationship or a nonterminal original order (AWAITING_ACCEPTANCE/ACCEPTED/DISPATCHED). Thus disconnected terminal threads are readable only; reconnect restores sending. Counterparty suspension does not revoke the active original party's historical/open-order authority, but inactive recipients get no notice. Pair guards serialize relationship, lifecycle and messaging admission before current account/session authority; message append then takes the order advisory lock only and never subsequently acquires inventory/configuration locks. No order revision/event/stock mutation follows a message.

Only text is accepted: NFC/strip, nonblank,1–4000 code points, internal LF/tab/whitespace preserved, other ISO controls/NUL/unpaired surrogates rejected; plain text is never interpreted. Immutable message captures actor/org/display name/time. Own organization sees actor ID/name; counterpart sees explicit nulls. Corrections append; there are no edit/delete/attachments/read-receipt APIs. Pagination reuses authenticated24-hour order cursors with separate MESSAGES view, org/order/size binding and original expiry, chronological millisecond UTC/id ordering. Same-millisecond appends advance UUID ordering under the order guard.

Creation requires canonical UUIDv4 Idempotency-Key. Actor/org/operation/key scope is shared across target orders; versioned keyed canonical payload binds target+normalized text. Reuse for another target/text conflicts, another account has its own scope. The pinned compatibility fingerprint key, not rotating revision/cursor key, identifies message successes. Nonblocking scoped-key advisory admission precedes party locks. Message, replay original success, mandatory body-free audit and MESSAGE_CREATED recipient/channel intents commit atomically. Exact retries reauthorize current actor and original-object access, then reconcile the committed result before rechecking new-write lifecycle/connection conditions; reconciliation performs no new send. Seven-day original success expires exactly at168 hours; retain account-lifetime target/message/digest tombstones, compact only replay result, never commercial text. REPLAY_EXPIRED includes resourceId. Definite rollback retries remain bounded; unknown outcome requires exact-key reconciliation, no blind uncertain retry.

Schema43 adds immutable order_message, guarded message_replay with original-result-only compaction, and recipient/channel message_notice/message_delivery intents. All current active verified counterpart members receive three queued channels; locale captured at enqueue, preferences/destination/access rechecked by later workers. No external payload, audit or new metadata field contains message body, amounts or individual counterpart authors; message notices reference safe organization/order/message identity. Delivery is queued intent, not provider/in-app delivery. SQL source/scope/deferred guards require actual message/replay and all eligible recipient channel intents. Runtime gets SELECT/INSERT only plus UPDATE(original_result) for replay compaction; no commercial/audit UPDATE/DELETE/read grant. Readiness43 and schema42 migration compatibility required.
