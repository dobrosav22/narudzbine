# Remaining OAuth and recovery capability retirement — selected 2026-10-21

Delegated D-GOV-005 / D-PLAN-018 / R-PLAN-018 refinement, selected before dependent code. Follow the verified schema65 session batch and the test fixture pacing gate. This document is design, not executed schema66 evidence. Backend/infrastructure only; no API or legal/commercial purge.

Three bounded thirty-elapsed-day jobs complete additional current-row capability classes while retaining original source rows/account/session/operation identity. Use one injected UTC millisecond cutoff per SQL call, expiry/ID order, at most1000 and FOR UPDATE SKIP LOCKED, separate ten-second REQUIRES_NEW jobs. Run after existing encrypted source/verifier retirement; exchange cleanup precedes flow binding cleanup. No provider retry or fabricated resolution.

* Exchange code: retain original challenge ID as the row primary key (already globally unique/non-null), make code_hash nullable with uniqueness for present codes. No foreign key currently points to the code hash. Initial code remains mandatory; exact nonnull-to-NULL update is one-way and cannot change other fields or permit subsequent consumption. Require old expiry/authentication and consumed_at when present, completed old parent and already-retired parent encrypted verifier. Original challenge/subject/account/authentication/consumption evidence remains, and one row per original challenge prevents re-creation. This is a short-lived one-use code, not a lifetime client idempotency key.
* Flow bindings: retire state_hash, browser_binding_hash, original_token_hash and native_challenge together only after the encrypted verifier is NULL, flow expiry/creation are old, state is OPEN or COMPLETED and no retained exchange code remains. Keep original account/session/provider/purpose/transport/epoch/outcome. State hash NULL is the one-way retired marker; initial state hash is still required. Relax purpose/transport checks only for the exact all-retired shape; preserve ordinary original-context checks. Retired flows cannot be claimed/restored. The exchange reader explicitly rejects missing verifier/native challenge before conversion/use; callback already rejects a missing verifier. No late Clock rollback can revive these capabilities.
* Recovery acceptance: add an internal immutable acceptance_retired flag, initially false. Only exact token_hash nonnull-to-NULL plus false-to-true flag update is permitted, preserving revision/state/source/consumption metadata. NOTICE_PERIOD may omit its hash only in this explicit retired state; insertion cannot bypass initial policy. Do not retire EVIDENCE_REVIEW or RECONCILING work. Require old case expiry/creation/update, absent encrypted acceptance copies and no SENDING/UNKNOWN delivery. Linked email/credential reconciliation or recent terminal updates defer retirement. Existing reader rejects NULL; retired cases cannot later consume acceptance, restore a hash or clear the flag. No case outcome is changed for retention.

Supply narrow field grants and aggregate read-only preview, preserving existing broader command permissions behind guards. Initial/restore/mixed-update/delete/retired-consumption cases must be tested. Verify all three cutoffs/deferred-source ordering, nullable consumption timestamps, completed/unconsumed exchange, browser/native LOGIN/LINK/REAUTHENTICATE shapes, bounded/racing workers and rollback, original source/account/session/history preservation, populated65 repeated migration and real HTTP callback/exchange/recovery denial (including Clock rollback) plus permission-isolated job deferral. Full wrapper, separate review and change-triggered packaged artifact checks remain mandatory before verified status. Inbox/delivery metadata, legal holds/assisted fulfillment/restricted tooling, independent deletion/audit archive/restore and actual external gates remain.

New exchange insertion also locks and checks its original live native bindings (state/verifier/native challenge) so a retired parent cannot produce another exchange capability. Existing callback writers already have the necessary source row-lock authority. This is source-integrity enforcement, not provider verification. Older proof-reader checks are isolated to their original five-field services; new whole-maintenance scenarios must test the later binding jobs.
