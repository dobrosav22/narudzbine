# Native image processing refinement

2026-10-20, assistant selection under D-GOV-005; implements R-CAT-049/050/068/069/070/076/077/080 and R-PLAN-013. This is a design refinement, not a claim of executed checks.

Use the approved ImageMagick 7.1.2-34 source, publisher SHA-256 `55fe0ec246245b46c429f9e6bc65294ad4a78a66b88abd9817971ca157856323`, built in the pinned Linux AMD64 Temurin toolchain. Resolve codecs/build dependencies from authenticated official Ubuntu archives with complete exact package locks; the proposed signed snapshot `20261016T000000Z` failed502/503 during qualification. Keep native package/version/license evidence separate from the Java dependency inventory. Fail startup when enabled processing cannot qualify its native sandbox; disabled remains the local default. No provider provisioning is implied.

The native child runs nonroot, with a private job directory, no inherited credentials, no shell, no delegates and only JPEG/PNG/WebP coders. Linux Landlock ABI1 or newer confines reads to the fixed native installation; default-deny seccomp permits only the necessary read/memory/stdio/clock/signal-handler/exit operations. All filesystem writes, network, process creation/execution, process signaling and resource-limit changes are denied. Images travel through stdin/stdout; no disk spilling. Require the actual sandbox self-test to pass; do not fall back to unsandboxed decoding. Fixed resource limits supplement the parent ten-second deadline. Preflight bounded image headers before decoding: dimensions at most6000 and20MP, reject APNG/animated WebP and multiple JPEG images. Normalize orientation, sRGB (including embedded ICC transformation), strip metadata, preserve format/transparency, resize longest edge2048; JPEG/WebP quality85, PNG lossless, output at most5MiB. Verify output format/dimensions/bytes/hash before storage.

One durable processing job per confirmed source uses an expiring fenced lease. A worker claims under the existing vendor/asset/source lock order, marks PROCESSING and records progress atomically. Storage/native work occurs outside transactions. Reclaim expired work; stale workers cannot publish or fail a newer attempt. Storage/network unknown outcomes leave work recoverable rather than classifying valid input as malformed. Definitively invalid media becomes FAILED with a stable code and retains raw bytes until the existing one-hour cleanup policy applies. Live leases exclude raw cleanup.

Processed keys are deterministic from vendor/asset; the verified content hash is their immutable identity, not a key suffix. Conditional writes and re-verification make lost provider responses repeat-safe. Publication atomically checks the current lease and stored proof, freezes processed identity, sets READY/ready_at/unreferenced_at, completes the job and appends a technical event. No business permission is invented for an internal worker; later attachment still checks current catalogue authority. A worker-only storage port reads bounded raw bytes and writes processed bytes, never exposes raw through HTTP. Runtime database grants explicitly distinguish HTTP columns from processing proof authority in deployment guidance.

Successful publication schedules repeat-safe raw removal using the existing storage tombstone fence; only the source's raw_deleted_at/event changes, READY remains intact. A crash after provider write, publication or raw deletion must recover without duplicate publication or deleting a retained processed object. Processed delivery and unattached/detached24-hour deletion remain a separate batch. No new HTTP operations are introduced.

Qualification refinement before code: the local Docker kernel is5.15.167.4, predating Landlock ABI3. Select an in-memory MagickWand child with stdin/stdout bytes instead of path-based CLI output. Require Landlock ABI1 for read confinement, and seccomp deny **all** filesystem writes (including open/openat write/create/truncate flags, openat2, truncate/ftruncate and pathname mutations), all network/process creation/execution. This closes the truncation gap on ABI1 rather than weakening confinement. Only fixed installation reads and already-open stdio are available; disk spilling is disabled (0 within the approved64MiB ceiling). Memory/map ceilings remain128MiB each; resource exhaustion fails processing rather than escaping to disk. Java owns private temporary files outside the sandbox. Require actual denial tests. No arbitrary CLI/script command interface is exposed.

Pre-code persistence refinement: use the single deterministic `processed/<vendor>/<asset>` key (without hash suffix), with immutable conditional content identity, to avoid untracked objects from stale attempts. A different processing algorithm requires a reviewed migration/reprocessing policy. The processing credential is a separate least-privilege database login; ordinary HTTP grants still cannot write processed proof. Three claimed attempts bound infrastructure/crash recovery; exhausted work becomes FAILED/SERVICE_UNAVAILABLE and follows raw TTL. A120-second fence covers bounded download/decode/upload/publication; no provider calls hold locks. READY raw deletion is a separately retried step and cannot demote READY. Snapshot service returned502/503 repeatedly; qualification may use authenticated official Ubuntu archives with exact package locks instead. Never use unauthenticated package indexes or floating dependency versions in the final build.

Separate review refinement before final sandbox changes: use a default-deny syscall allowlist, including read-only open flags and limited descriptor queries, rather than a denylist. Otherwise an exploited decoder could signal or change resource limits on another same-UID process even with filesystem/network confinement. Set its own hard resource limits before loading seccomp, then permit only memory, stdio, read-only configuration/metadata, clocks, signal handling and process-exit primitives. Kernel/provider qualification remains fail closed. The internal list-length budget8 covers ImageMagick's internal pixel caches; actual source/image count is separately required to equal1 before and after decode.

Separate review refinement before cleanup changes: raw-TTL cleanup must also tombstone the deterministic processed key before recording DELETED, including when no processed object exists yet. This fences a paused worker that resumes a conditional processed PUT after losing its lease and after raw cleanup. READY raw removal does **not** fence/delete its retained processed key. Unknown cleanup outcomes retain the database claim for reconciliation; both zero-byte storage fences are permanent. The future processed24h cleanup must preserve this same late-write protection.
