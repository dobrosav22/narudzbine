## Verify

Use Temurin 25.0.4.1+1 and a running Linux Docker engine. From this directory:

```powershell
./mvnw.cmd -B -ntp -s .mvn/settings.xml verify
```

Linux: `./mvnw -B -ntp -s .mvn/settings.xml verify`.
The only-script wrapper verifies the Maven 3.10.0 archive checksum. Enforcer rejects an incompatible Java or Maven version. The settings file restricts artifact resolution to Maven Central. Docker absence fails integration tests; no H2 substitution or automatic skip exists.

Tests exercise PostgreSQL 18.6 by digest, repeat-safe migrations, runtime DDL denial, empty/incompatible/unavailable DB startup failure, private management/public denial, runtime readiness loss, architecture boundaries, request-log redaction and OpenAPI references. Reports are in `target/surefire-reports` and `target/failsafe-reports`; CycloneDX inventory is `target/bom.json`.

The local workspace toolchain, if prepared by the agent, lives under ignored `../.tools`; it does not replace machine-wide Java/Maven. Build dependencies may be cached there with `-Dmaven.repo.local=<absolute-path>`.

## Database and process

Provision a disposable PostgreSQL 18.6 database for development. Use a schema-owning migration role and a distinct runtime role with CONNECT/USAGE and only required table permissions. Runtime needs SELECT on `backend_schema_version` and `flyway_schema_history`; it must not own the database/schema or have CREATE, superuser or role-management rights. Future migrations grant only their required business DML. The integration suite demonstrates this separation.

Supply configuration through the environment or a local secret manager, never command-line secret arguments or tracked files:

| Variable | Purpose |
|---|---|
| DATABASE_URL | JDBC PostgreSQL URL; hosted connections require TLS verify-full |
| DATABASE_USERNAME / DATABASE_PASSWORD | Runtime-only role |
| MIGRATION_DATABASE_USERNAME / MIGRATION_DATABASE_PASSWORD | Separate migration identity, only in the release process |
| PORT | Public business listener, default10000 |
| MANAGEMENT_PORT | Loopback-only management listener, default9091 |

Run the controlled release step with `java -jar target/narudzbine-backend-0.1.0-SNAPSHOT.jar --migrate`. This starts no HTTP server; Flyway serializes migrations and failure stops the command. Do not give the normal application process migration credentials. Then run the same JAR without `--migrate` using the runtime role. Startup validates schema/version/checksums before configuring listeners; it never migrates. JDBC timeout/pool limits, Hibernate validation and OSIV=false are configured explicitly.

Management health/info/metrics are bound to127.0.0.1 on the separate port. Do not publish that port. Readiness checks database/schema; liveness does not restart a healthy process because the DB failed. Public requests return503 while database/schema readiness is lost. Render private monitoring/connectivity remains G-03; loopback defaults do not prove hosted topology.
