Two short Read Committed transactions use organization→account/session→qualification lock order. Phase1 locks original case organization (including suspended/closed), authenticates current platform session, checks fresh authentication/CSRF, takes a shared qualification guard and commits PRIVACY_REVIEW_AUTHORIZED plus immutable access identity/reason/context. A random32-byte nonce remains inside the request; only its SHA256 digest is stored. Bind exact case/original organization/country, actual operator/session/transport, qualification revision, security epoch, credential generation, original session token hash and sixty-second expiry. The nonce is never returned to clients, logged or serialized in diagnostic representations. No Idempotency-Key: each review is a new audited inspection; repeat after response loss creates another authorization without changing the case.

Phase2 re-locks original organization, reauthenticates current session/CSRF/freshness and qualification, then invokes a fixed SECURITY DEFINER projection. Ordinary runtime retains no SELECT of privacy_case.private_reason/requester_id and no qualification DML; EXECUTE alone cannot bypass the committed authorization. The projection requires the matching nonce, unexpired current binding and an access row created by a different top-level transaction. PostgreSQL MVCC does not expose another transaction's uncommitted row; rejecting the creator's own XID therefore prevents SELECT→ROLLBACK from removing the only authorization evidence after disclosure. Savepoints retain the same top-level XID. Actual disclosure appends PRIVACY_CASE_PRIVATE_READ plus access linkage in phase2, records successful activity, commits, and only then returns a no-store response. If phase2 fails or the response is lost, the previously committed authorization remains as conservative evidence of possible access; do not pretend it is proof of a successful read. No raw data is returned on audit/commit failure. Current qualification revocation, account/session removal and credential changes serialize with both committing phases; revision/epoch/token changes invalidate older permits, including revoke/re-enable.

The response contains case ID, original organization/country/kind/requester account ID/request reason/creation time and review authorization ID. It includes no commercial dataset, third-party contact directory, credentials or private support evidence. Original case state stays REQUESTED. Qualified operators may inspect both domestic countries and retained cases after organization closure; neither creates business membership or commercial write authority.
