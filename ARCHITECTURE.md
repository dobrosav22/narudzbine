## Package boundary graph
Each named business package contains api (public ports/immutable domain projections), application (use-case orchestration), domain (invariants) and infrastructure (JPA/SQL/provider adapters). Controllers use own application layer; repositories/entities stay private. Shared contains primitive IDs/money/time/errors/authorization context and generic outbox/audit ports, not domain repositories.
- identity and organizations own their aggregates; identity consumes organization authorization through an organizations.api read/lock port. Organizations uses an identity-owned revocation port defined as a narrow shared security contract, not identity infrastructure.
- catalogue owns products/taxonomy/units. pricing and inventory depend on catalogue.api. Catalogue activation/combined saves invoke narrow eligibility/correction ports declared in catalogue.api, implemented by pricing/inventory; catalogue imports neither implementation package. Read adapters and command services are distinct beans to avoid constructor cycles.
- Agreed-price persistence depends on trading.api for current immutable relationship parties/generation and confirmation summary updates. Identity transport acquires both party guards in UUID order before actor/session locks; pricing never imports trading implementations. Domain trading registration is independent of HTTP/setup exposure flags.
- subscriptions owns revision/assignment/cap services; trading depends on organizations.api and subscriptions.api. All quota-affecting commands use the same assignment guard.
- buyerworkspace owns drafts/favorites without depending on ordering. ordering orchestrates catalogue/pricing/inventory/trading/organizations/buyerworkspace through their public APIs in one DB transaction; reorder projection lives in ordering and consumes buyerworkspace only for explicit save.
- notifications and audit consume committed outbox contracts, never call back into command services. media implements catalogue media port. reporting uses parameterized read-only SQL projections with explicit tenant predicates; it may read defined snapshot tables but never write other aggregates.
- shared imports no business package. No package accesses another package's domain/infrastructure or repositories. ArchUnit asserts these exact constraints; API-level dependency exceptions above are explicit, not a blanket acyclic-graph claim.

Transactions are owned by the outer application use case, not controller/repository side effects. Services joining a command do not independently commit. Read Committed with locks/constraints; reports read-only Repeatable Read. Provider I/O only after business commit, except independent auth exchanges governed by credential-operation barriers. Open EntityManager in View disabled; DTO mapping/fetch plans complete inside service boundaries.

No separate message broker/cache/search cluster, no native-image/reactive stack, no business-event microservices or user-facing AI feature. PostgreSQL leases/outbox and immutable images support later scaling without changing approved business effects.
